# 低成本作业方案 · xgsz-maintain（设备维修工单平台）

- 编写：DSH，2026-11-09
- 适用：本仓库后续所有开发会话（DSH / WorkBuddy / Trae 通用）
- 依据：`项目说明/周报-20261108.md` 的「四、待完善」与「六、下周计划」

---

## 0. 一句话

**一个会话只做一个工作包；进来先读交接文件，出去必须写交接文件。**
目标：单会话上下文 ≤ 8 万 token，单包花费 ≤ $0.3。

---

## 1. 钱到底花在哪（真实账，不是估计）

会话「维修工单平台开发任务」的账本数据：

| 项 | 数值 |
|---|---|
| 总花费 | **$6.39** |
| 模型调用次数 | **2239** |
| 平均单次上下文 | **≈ 44.4 万 token** |
| 缓存重读合计 | **9.93 亿 token**（占花费约 47%） |
| 输入 / 输出 | 437 万 / 121 万 token |

结论：**贵不在"写代码"，在"2239 次调用每次都把 44 万 token 的历史重读一遍"。**
仓库代码没变大，是会话在变胖。同一个会话里既改前端、又改后端、又排障、又审计，
每切一次话题，旧话题的全部内容都跟着重新计费。

拆开做单包的预期（60 次调用 × 5.5 万上下文）：
**≈ $0.1 ~ 0.3 / 包**。下面 9 个包全做完约 **$1 ~ 2.4**，
比旧会话一次性花掉的还少。

## 2. 四条硬规则

| 编号 | 规则 | 目的 |
|---|---|---|
| **R1** | 一个会话一个工作包，≤ 2 小时、≤ 80 次调用，到点就停 | 上下文不越过 10 万 |
| **R2** | 开场只喂**交接文件 + 3~5 个目标文件**，禁止"先把整个项目看一遍" | 起步上下文从 44 万降到 2 万 |
| **R3** | 收尾三件事：跑冒烟、`git commit`、写下个会话的交接文件 | 三件不全不算完成 |
| **R4** | 单会话花费 > **$0.6** 或调用 > **100 次**，立即停手写交接、换会话 | 硬刹车，不靠自觉 |

> 看数：上下文用 `/context`，费用看右下角/侧栏计费挂件。

## 4. 交接文件标准（七段，缺一段下个会话就废）

放 `项目说明/交接/W0x-<主题>.md`，模板见同目录 `_交接模板.md`：

1. **目标**（一句话）+ **不在范围**（明确不做什么）
2. **现状**：3~5 个文件 + 关键行号 + 当前行为
3. **约束**：不许动的部分（14 态状态机、归档六项校验、鉴权中间件、品牌名「芯光数智」）
4. **验收标准**：可执行命令 + 期望输出
5. **已完成 / 未完成**：精确到函数名
6. **回滚办法**：commit hash 或 `alembic downgrade -1`
7. **下一个会话的第一句话**：可直接复制粘贴

## 5. 两种开场白（直接抄）

**开新包：**

```
继续 xgsz-maintain。先读 项目说明/交接/W0x-xxx.md，只读它列出的文件，
不要浏览整个仓库、不要重新审计。预算 ≤80 次调用。
做完按 _交接模板.md 写交接文件，并在 backend 目录跑冒烟：
.\.venv\Scripts\python.exe ..\tools\smoke_test.py
```

**续做被打断的包：**

```
读 项目说明/交接/W0x-xxx.md 的「已完成 / 未完成」两段，
从「未完成」第一项接着做，不要重做已完成部分，不要重新审计，
不要顺手重构工作包以外的代码。
```

## 6. 省钱动作清单（按效果排序）

1. **别用截图问"这页哪里不对"** —— 一次截图几百 KB 进上下文，还是输出。改成让它读 `.vue` 文件 + 接口返回，或装 `dsh-design-studio` 用 `check_design` 出结构化结论。
2. **探查类任务丢给子代理** —— "库存扣减在哪实现"这种，subagent 独立上下文、只回结论，不污染主会话。
3. **需求一次问全** —— 每次往返都带着整个上下文重算。开工前把 3~5 个待确认点一次列清。
4. **`/compact` 用在换话题处**，不要用在大改中间（会丢刚建立的细节）。
5. **不要回去续那个 44 万上下文的旧会话** —— 历史已沉底，续做等于继续按 44 万/次付费。要做就从交接文件新开。
6. **重活放低谷时段**（峰谷倍率见计费挂件），同样工作量能再省一截。
