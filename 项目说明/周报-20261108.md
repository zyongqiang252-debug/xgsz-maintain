## 三、已完成明细

### 1. 平台本地跑起来（交付前提）

- 无 Docker 环境方案：便携版 PostgreSQL 16（15432）+ Python 3.12 venv + 前端构建产物
- 一键启动脚本 `tools/start-local.ps1`，一键建库、灌数据、冒烟
- 数据库 19 张表 + pg_trgm 全文索引，Alembic 从零建库一次通过

### 2. 品牌与图标

- 全站品牌统一为「芯光智数」，残留的旧项目名只在文档注释里
- 新图标：白色扳手 + 齿轮，蓝青渐变（沿用公司 logo 色系），含 iOS 主屏图标
- 图标生成器脚本化，改参数可重新出图

### 3. ① 工单导入（重点）

| 入口 | 能力 | 实测 |
|---|---|---|
| Excel / CSV | 表头自动识别、中文字段别名映射、逐行规范化与校验 | 3 行 → 2 条待确认 + 1 条因缺故障描述被拦；**500 行 1.26s** |
| 编码兼容 | UTF-8 / UTF-8 BOM / **GBK** | 三种编码均通过 |
| 图片 OCR | 本地 RapidOCR，不联网 | **0.87s/张，识别 199 字**，全字段提取正确 |
| PDF | pdfplumber 解析 + 大模型抽取 | 解析 2.04s 成功；抽取需 API Key |
| 入库流程 | 待确认清单 → 人工编辑 → 确认入库 → 原图自动挂附件 | 全流程验证通过 |

**流程**：上传 → 自动识别表头 → 字段映射 → 逐行校验 → 待确认 → 人工确认 → 生成工单

校验已收紧：空表拒绝、伪装文件给中文提示、**重复工单号/负工时/超长字段在导入阶段直接标错**（不用等确认入库才报错）。

### 4. ② 工单生命周期（重点）

- 状态机 14 个状态值，主链路九态全通：
  `DRAFT → SUBMITTED → ASSIGNED → ACCEPTED → ARRIVED → INSPECTING → IN_PROGRESS → ARCHIVING → ARCHIVED`
- 每次流转写进度日志，实测 **8 条**逐跳留痕
- 归档校验：故障描述/现象/根因/方案/结果/工时 **六项齐全才允许归档**，不达标列出缺失项
- 角色权限：维修员（接单/推进）、主管（派工/退回）、管理员（全量）矩阵已验证
- **修复**：原来编辑一次草稿会自动跳到「维修中」，跳过 5 个状态 → 已改为显式「提交报修」，并给「提交完成」加了状态前置校验

### 5. ③ 知识库与 AI 问答（可选任务）

- 知识库增删查、检索接口正常；无 Milvus 时自动降级 BM25，命中 score 0.97
- AI 问答 SSE 流式接口连通，能返回引用来源
- **限制**：未配 DeepSeek API Key，答案生成、PDF 智能抽取、知识自动收录三块暂时只有空结果
